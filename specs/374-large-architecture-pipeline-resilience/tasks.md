## Format: `- [ ] T### [P?] [US<id>?] (W<n> · <lane> · <agent>) <action> (<effort> d) — <exact file path(s)>`

- **[P]**: the task touches no file that another task in its wave touches, and depends on no incomplete task.
- **[US<id>]**: the spec's story ID: US1a, US1b, US2, US3, US4, US5, US6a or US6b. Setup, Foundational, Rulings, gate and Close-out tasks carry none.
- **Wave**:
  - W0–W6 for PR 1;
  - W1′–W6′ for PR 2. W1′ is PR 2's setup and rulings, and runs inside PR 1's W2–W3.
- **Agent**: only names from `.claude/agents/_README.md`.
  - The `tachi-*` agents are subjects under test, never assignees.
  - The team-lead assigns and signs off, and is never an assignee (`/aod.tasks` Step 6). Gates go to `orchestrator`, which also integrates every wave.
- **`[BLOCKED until <item>]`** opens the action of a task that waits on a PR 2 ruling (TW-ADR) or on S-9's table. A blocked task is never `[P]`.
- **Effort**: eng-days at the agent-orchestrated pace (feasibility §2). Every task is 0.1–0.5 d.
- **Live tasks** run in scratch adopter projects, with `tester` driving a Claude Code session. Their evidence is `[MANUAL-ONLY]` in the spec's sense.

## Hygiene rules (every task)

- **H1, no gated run in the main tree.** No pytest, extractor or renderer runs in the main tree. Gated suites, oracles and every renderer or extractor run happen in a scratch clone of the committed tip, because #365's tests re-render tracked example PNGs. For the same reason `/aod.build` runs with `--no-tests`. After any agent returns, check `git status`, and discard any stray change under `examples/**`; never commit one.
- **H2, no baseline images.** No PDF baseline is regenerated, and no re-rendered example PNG is committed.
- **H3, explicit staging.** Stage only explicit paths, as in `git commit -m … -- <paths>`. Never use `git add -A` or `git add .`.
- **H4, the init baseline.** An edit to any of the 61 init-baseline substitution targets regenerates `tests/fixtures/init-baseline-tree/` in the same commit. Run `tests/fixtures/regenerate-baseline.sh` in the integration tree that holds the edit, then run the substitution tests (Test-1) in a scratch clone of the resulting commit (AR-T11).
  - The planned targets are `docs/architecture/01_system_design/README.md` (T024, T136), `docs/INSTITUTIONAL_KNOWLEDGE.md` (T080), and `docs/devops/CI_CD_GUIDE.md` (T080, T136). `.security/` already holds a target, so T068 and T126 re-run the script's target selection before committing there.
  - A task that finds it must edit another target adds the regeneration to its own commit.
- **H5, no commit mid-write.** Never commit while a dispatched agent is still writing: the pre-commit hook stashes unstaged files. Agents never commit. The orchestrator commits once every lane of the wave has returned. For a mid-wave hand-off, the orchestrator commits a returned task's paths on its lane branch, in that lane's own worktree, where no agent writes; dependents cherry-pick that commit, and the wave still integrates once (TL-T13).
- **H6, commit before gating.** Commit before any gated run, because the harnesses clone the committed HEAD. Push once per wave, and never push a records-only commit on its own (TW-CI).
- **H7, lock-step wiring (KB 3, FR-E.5).** These land in one commit:
  - a test module, its input surfaces, its `paths:` entries and its invocation line;
  - each new shipped script or helper, in `INSTALL_MANIFEST.md`'s three places, `REQUIRED_SCRIPT_NAMES`, the allowance of F-373's S-13 import gate and `ENTRY_SCRIPTS_IMPORTING_PARSERS` (F2);
  - a newly gated module, in ADR-050 D16's coverage include list (H15).
- **H8, public hygiene (NFR-6).** This file, every `test-results/` record, commits, PR bodies and release notes carry:
  - no local or absolute user path;
  - no real-world target name;
  - no real finding or report content.

  Fixtures are synthetic, and the SC-3 transcript audit stays private. TW-N3 stays generic. The Architect re-review's findings are cited as RR1–RR6, so #397's items keep their N-numbers.
- **H9, worktrees.** Each lane works in its own worktree, off its wave's base, and is integrated by cherry-pick. A dependent lane cherry-picks a predecessor's lane-branch commit (H5) into its own worktree, and never reads another lane's uncommitted files. Another session may own the main checkout, so no lane switches branches there.
- **H10, tools and commands.** No agent gains a tool (NG8), and every command keeps `{description}` (C5). The one frontmatter change is D14's removal of the report agent's `Agent` tool in PR 2, committed with §8.3 (C7).
- **H11, before delivery.** Before any delivery merge or push, the branch is current and `main` equals `origin/main` by a full-tree diff (KB 18).
- **H12, issues.** Before filing issues, export `AOD_REPO` and dry-run the titles, because `create-issue.sh` overwrites an open issue whose title phrase-matches.
- **H13, portability (NFR-9).** Every command and orchestrator fence is a single `python3` invocation with literal arguments (C6). That holds on bash 3.2 and on BSD and GNU userlands by construction, and `test_contract_text_374.py` pins it. `tachi-pytest.yml`'s two-OS matrix still runs on every push that touches a command.
- **H15, coverage counts in-process runs only (ADR-050 D16; C3).**
  - **Tests drive entries in-process.** Gated tests load each hyphenated entry through `tests/conftest.py`'s loader and call `main(argv)`. Subprocess cases cover only what a process alone shows, such as exit codes on a real interpreter. Subprocess runs don't count toward coverage, so W1's push, the cut line, could otherwise fail the gate.
  - **Entries keep the populator's shape:** their work in `main(argv=None) -> int`, behind a thin `__main__` guard.
  - **Wiring.** Each newly gated module joins ADR-050 D16's coverage include list in its wiring commit (H7).
  - **The parser ratchet (E3).** Each new parser function's unit tests go in `tests/scripts/test_tachi_parsers.py`, the file the ratchet measures. The floor is never lowered (ADR-050 D16).
- **H14, two PRs at once (TL-T4).**
  - **Five lanes, counted across both PRs.** PR 1's conditional fix lane (T146, T147) counts. While it runs, PR 2 yields its lowest-priority lane: in W2′, O2 holds T094 (T093 already ran in W1′, during PR 1's W3); in W3′, P′ slips first (T120, T121), within W3′, where it has 0.65 d of slack, so that T124 still finds T120's Scope page (TL-T16).

The lane with the longest remaining W2′ chain always holds one of the two: OC in the base case, and OS when O-α's or O-β's contingency fires. Tasks already in flight finish; the rest wait for a slot, and the orchestrator records each wait.
    - **Priced:** +0.05 d on W2′, in the base and in the all-three case, since every other lane's slack covers its wait.
    - **The alternative:** a full hold (no PR 2 dispatch at all) would cost about +0.35 d, because T117 and W3′'s start would wait for W5's end. So the throttle is the rule.
    - **T104** starts only once each W2′ lane's first task is in flight, so the spike never freezes W2′'s start.
    - **In W3′,** O2 and O3 hold the two slots while a PR 1 live run is in flight. That keeps W3′'s throttled start at about +0.1 d, and the projection table carries it: PR 2 is about T0 + 14.0, within its bound of T0 + 15.0 (F8) (Team-Lead confirmation, v1.2).
    - **Escalation.** The first usage-limit interruption of a PR 1 live run turns the throttle into a full hold, with no PR 2 dispatch, until that live wave ends. The interruption is not an attempt under TW-L2 (Team-Lead confirmation, v1.2).
  - **Usage.** If a usage window runs out during a live run, that run is interrupted, not failed: TW-L2 doesn't count it as an attempt (T077, T133).
