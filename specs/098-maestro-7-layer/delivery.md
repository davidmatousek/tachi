## What Was Delivered

The MAESTRO "Risk by MAESTRO Layer" coverage matrix now **always renders all 7 canonical layers (L1–L7)** in canonical L1→L7 order across both output formats, eliminating the "silently dropped" failure mode where zero-finding layers were omitted and the matrix read as a coverage ceiling (e.g. 2-of-7).

- **Full scan span in both views** (US-1, P1): `threats.md` "Risk by MAESTRO Layer" table and the PDF "MAESTRO Layer Analysis" page both list all 7 canonical layers in canonical order, regardless of finding count. The authoring directive was flipped from "omit zero-finding layers / order by severity-descending" to "always emit all 7 in canonical L1→L7 order" at the single source of truth — the orchestrator's markdown-authoring directive (`.claude/agents/tachi/orchestrator.md`), mirrored in the output-schema contract (`.claude/skills/tachi-orchestration/references/output-schemas.md`) (FR-001, FR-002, FR-006).
- **Self-documenting zero-finding rows** (US-2, P1): every zero-finding layer shows a `0` count plus the Model A annotation `Analyzed — no findings this scan`, cross-format identical (markdown cell carries no trailing period; Typst prose carries one — the only sanctioned difference). Reads unambiguously as coverage metadata, never a severity, and does not contradict the STRIDE matrix's `---`/`n/a` vocabulary (FR-004). The conditional Unclassified row is preserved, positioned after L7 (FR-005).
- **PDF carry-through** (FR-003): the downstream zero-finding filter at `scripts/extract-report-data.py:407` was removed so zero-finding layers reach the previously-dead empty-layer branch in `templates/tachi/security-report/maestro-findings.typ`. The PDF data model is seeded from the parsed markdown table, so it can never show more layers than the markdown authored (single source of truth; SC-003).
- **Regression-proofed completeness** (US-3, P2): new `tests/scripts/test_maestro_coverage_invariant.py` asserts every `examples/**/threats.md` carrying a MAESTRO table contains all 7 canonical L-IDs (heading-level-agnostic discovery; excludes `test-output/` snapshots), plus a unit assertion in `test_extract_report_data.py` that the 7-layer retention survives extraction (FR-009).
- **Complete example regeneration** (FR-007, FR-008): 9 example `threats.md` regenerated to 7 canonical rows via a new stdlib helper `scripts/populate-maestro-coverage.py` (examples-regeneration tool, NOT wired into any command or orchestrator phase); 6 gated PDF baselines regenerated byte-identical under `SOURCE_DATE_EPOCH=1700000000`; the 3 h3 headings normalized to `####`.
- **No SARIF / schema change** (FR-010): verified by diff — layer counts were already structured; this is a markdown + PDF rendering change only. `/aod.analyze` clean (SC-005).
- **Release framing**: `CHANGELOG.md` `feat(098):` entry.

**Out of scope / by design**: Model B (clean-vs-`n/a` two-state annotation) was deferred to follow-up #311 — it needs `component_layer_map` data computed in a different pipeline. The `maestro-stack` infographic completeness was deferred to #312. A CI drift-gate for the coverage matrix was filed as #313. None are close-gates for Issue #98.

## Lessons Learned

| Category | Lesson | KB Entry |
|----------|--------|----------|
| Technical Pattern | The markdown "Risk by MAESTRO Layer" table is the single source of truth; the PDF data model is **seeded from the parsed markdown**, so the fix belongs at the orchestrator authoring directive (`orchestrator.md`), not the downstream PDF filter (`extract-report-data.py:407`). Treat downstream extractors as carry-through that should only ever *narrow* from the source, never widen it. Verify the seeding relationship before deciding where a multi-format render fix belongs. | Entry 11 in INSTITUTIONAL_KNOWLEDGE.md |
