## T005: Stream 1 Day-1 Baseline Benchmark (Pre-Refactor) (Date: 2026-05-05)

Methodology per SC-010: 100 invocations × 4 fixtures × p50/p95; per-file delta
(NOT aggregate); warm-cache + cold-cache reported separately. Each invocation
forks a fresh `bash -c 'source <fixture>'` so timings include process-fork +
bash-startup + source-parse + return — i.e., the end-to-end cost an adopter
incurs at /aod.update or init.sh time. Two warm-up invocations precede each
fixture's 100-run timing window to amortize first-run JIT/cache effects.

Environment:
- Host: Darwin 25.3.0 (macOS)
- Bash (local): GNU bash 5.3.9(1)-release (aarch64-apple-darwin25.1.0)
- Note: T011/T012 will run identical numbers on macOS bash 3.2.57 in CI
  (Day-5 slip-watch GREEN-LIGHT condition 1) — local 5.3.9 timings here
  represent steady-state developer-loop numbers. The relative per-file delta
  vs T013 post-refactor is what matters; absolute numbers will shift modestly
  on bash 3.2 but the comparison axis is held constant.

Fixtures benchmarked:
- Site A (init.sh:106) → stacks/nextjs-supabase/defaults.env
- Site A (init.sh:106) → stacks/fastapi-react/defaults.env
- Site B (template-git.sh:561) → tests/fixtures/config-load/valid/aod-kit-version-valid
- Site D (template-substitute.sh:209) → tests/fixtures/config-load/valid/personalization-env-valid

Note: Site C (template-substitute.sh:217/249/536/558) is `eval` removal — not
a `source` site — so no T005 baseline applies. T005 covers source-file load
sites only; Site C's measurement is "eval removed" (binary), not timing.

All four fixtures cluster within ~1.5ms p50 of each other (8.9-10.4ms),
indicating the dominant cost is bash-process-startup (~5-6ms baseline)
amortized over a small parse pass — file-content size at ≤300 bytes is below
the noise floor of process-fork variance. This means NFR-004's 25% threshold
(≤2.5ms p50 increase) will be tight; the post-refactor library MUST keep
per-call cost bounded by ~2-3ms over the existing source path to stay green.
