## Problem

OWASP released the Top 10 for LLM Applications 2026 (v1.0, cover-dated 2026-08-04) — the first evidence-tested edition, validated against 6,639 classified real-world incidents. Every tachi LLM-list mapping, emitted finding code, and the coverage page still targets the superseded 2025 edition. This is not a year bump: **the rank order changed, so bare codes changed meaning** (LLM03 meant Supply Chain in 2025; it means Excessive Agency in 2026), one entry was renamed and re-scoped (System Prompt Leakage → Hidden Context Exposure), and four entries absorbed new attack classes.

Until remapped, every emitted LLM finding cites a superseded standard, and the headline 50/50 coverage claim is silently stale. The harm lands hardest on tachi's target user — developers without deep security expertise who trust emitted codes and cannot self-detect that LLM03 changed meaning. As the upstream machine-readable contract for downstream AI-security tooling, tachi propagates the error to every consumer.

**The risk is not hypothetical — the repo has already fallen through this hole once.** Architect review (2026-08-05) found `scripts/generate-risk-scores-sarif.py` still ships OWASP LLM **2023**-edition category names ("Training Data Poisoning" for LLM03, "Model Theft" for LLM10) under a `version: "2025"` label, plus a retired `informationUri` — silent drift from the 2023→2025 transition that nothing caught. This PRD closes that hole class structurally, not just for this edition.

## Solution

A **category-level remap** (never code-level) of every LLM Top 10 mapping, emitted finding code, and coverage surface to the 2026 edition, governed by the official movement map as remap authority. The alias/cutover policy for emitted codes — including the exact `references[]` token grammar — is decided **first** via ADR (it constrains remap mechanics). Per-category coverage is **re-derived from detection evidence against 2026 definitions** — never carried forward. The four scope absorptions get a gap analysis; each gap is covered in-loop or filed as a follow-up issue. An explicit exclusion list protects immutable delivery records from the sweep.

**Scope split (team-lead C2, adopted)**: the contract surfaces — catalog, crosswalk, agent personas, skills, adapters, emitters, schemas, tests, coverage claim — ship in this feature. The `examples/**` derived-artifact refresh (47 files, 37% of blast radius, unbounded orchestrator-context cost) splits to **follow-up F-362b, blocking before the next minor release**, under a declared time-boxed carve-out (FR-8). F-362b inherits the CA-baseline regeneration gate (FR-7) because re-keying example findings is what moves those baselines.

## Movement Map (remap authority — from the 2026 release)

| 2025 code | 2026 code | Category | What to handle |
|-----------|-----------|----------|----------------|
| LLM01:2025 | LLM01:2026 | Prompt Injection | Rank holds. Scope now covers cross-modal attacks (instructions hidden in images or audio) |
| LLM02:2025 | LLM02:2026 | Sensitive Information Disclosure | Rank holds |
| LLM06:2025 | LLM03:2026 | Excessive Agency | Up 6 → 3 |
| LLM03:2025 | LLM04:2026 | Supply Chain | Down 3 → 4. Scope now covers model-artifact authenticity |
| LLM04:2025 | LLM05:2026 | Data and Model Poisoning | Down 4 → 5. Scope absorbs fine-tuning subversion |
| LLM10:2025 | LLM06:2026 | Unbounded Consumption | Up 10 → 6 |
| LLM09:2025 | LLM07:2026 | Misinformation | Up 9 → 7 |
| LLM07:2025 | LLM08:2026 | System Prompt Leakage → **Hidden Context Exposure** | Renamed and re-scoped (broader hidden-context trust failure) |
| LLM08:2025 | LLM09:2026 | Vector and Embedding Weaknesses | Down 8 → 9 |
| LLM05:2025 | LLM10:2026 | Improper Output Handling | Down 5 → 10. Scope spans insecure generated code at scale |

**Boundary note**: the 2026 release draws an explicit line between the model as a component (this list) and the model as an actor with tools, memory, and downstream consequences (OWASP Agentic Top 10, which tachi covers separately). Where a mapping decision is ambiguous, use the official crosswalk in the 2026 PDF Appendix A (LLM-to-ASI mapping matrix) — never invent our own.

**Catalog reality (architect HIGH-4)**: there is no `owasp-llm.yaml`. The LLM entries are 10 of 60 records inside the single six-list `schemas/taxonomy/owasp.yaml` (A / API / ASI / LLM / M / ML). The lexicographic id-sort invariant (`test_records_sorted`) holds after the remap because ids stay `LLM01..LLM10`; `full_id` is the one catalog field carrying the edition (`OWASP-LLM-2025-NN` → `OWASP-LLM-2026-NN`); each record's `# citation:` audit comment needs re-attestation, and no test sees comments.

## User Stories

### US-1: Findings cite the current standard (primary — verbatim from #362)
**When** I rely on tachi's OWASP-aligned threat modeling as a security engineer, **I want** every LLM Top 10 mapping, emitted finding code, and the coverage page updated to the OWASP Top 10 for LLM Applications 2026, **so I can** trust that tachi findings cite the current standard and the coverage claim stays verifiably true.

- AC: Given any LLM-list mapping (catalog, crosswalk, agent personas, skill references, adapters, schemas, templates), when the remap completes, then it is remapped **by category** per the movement map — no mapping survives on its 2025 code unreviewed.
- AC: Given the Hidden Context Exposure rename, when any user-facing surface shows the category, then it uses the 2026 name with "System Prompt Leakage (2025 name)" retained as an alias or historical note.
- AC: Given a repo-wide scan after the remap, when searching for suffixed forms (`LLM0N:2025`, "LLM Top 10 2025") **and** checking the bare-code disposition ledger (FR-13), then no unreviewed reference remains outside the FR-8 exclusion list (which includes the declared, time-boxed `examples/**` carve-out → F-362b).

### US-2: Downstream consumers survive the code transition
**When** my pipeline consumes tachi SARIF/finding metadata pinned to 2025 identifiers, **I want** a deliberate, documented alias/cutover policy, **so I can** migrate on a known contract instead of silently misinterpreting re-meaning'd codes.

- AC: Given the alias decision (FR-6), when the remap ships, then the choice between hard cutover vs dual-emission (2026 primary + 2025 alias for one release) is recorded as an accepted ADR **before** remap work begins, and the ADR specifies the exact `references[]` token grammar.
- AC: Given the enforcement reality that production `threats.md` and `.sarif` are LLM-authored (the SARIF scripts have no production caller), when the ADR is written, then it names the actual enforcement points — agent-persona prose, the 15 skill reference files, and `schemas/finding.yaml`'s contract example — and requires `generate-threats-sarif.py::normalize_owasp_id` plus a covering test to move in lockstep with the grammar (the current regex silently falls through to raw passthrough and has zero test coverage).

### US-3: The coverage claim stays honest
**When** I evaluate tachi's 50/50 OWASP coverage claim against the 2026 edition, **I want** per-category coverage re-derived from detection evidence against 2026 definitions, **so I can** trust the published number is earned, not carried forward.

- AC: Given the four scope absorptions (cross-modal injection, model-artifact authenticity, fine-tuning subversion, insecure generated code at scale), when the gap analysis completes, then each absorbed sub-class is either covered by an existing detection (with cited evidence) or its category drops to **Partial** and a follow-up issue is filed.
- AC: Given `OWASP_COVERAGE.md` is a hand-authored canonical reference (no generator exists), when it is updated to 2026, then correctness is gated by review against `schemas/taxonomy/owasp.yaml` and the re-derived verdicts (FR-9a); byte-determinism is verified where it actually lives — the CA-PDF baselines under the existing `SOURCE_DATE_EPOCH` recipe (FR-9b).
- AC: Given the re-derived verdicts, when coverage counts change, then the numbers are updated everywhere they appear (README lines 24/48, docs, site copy, `.claude/rules/scope.md`) — shipping an unchanged "50/50" without re-derivation is a PM veto at spec review.

## Risks

- **Bulk-replace correctness failure**: codes changed meaning; a find/replace authored for Supply Chain would assert Excessive Agency. *Mitigation*: category-level remap authority (movement map), per-edge dispositions (FR-5), bare-code ledger (FR-13).
- **False assurance from green CI**: the #329 drift guard is structurally blind to this change class and reports green throughout. *Mitigation*: FR-7 treats guard-green as uninformative; byte-identity suite green is the real pre-merge gate.
- **KB-15 repeat via deferred regen**: F-186 left the byte-identity suite silently red on main. The F-362b split re-creates that shape. *Mitigation*: carve-out is declared and time-boxed, F-362b is blocking-before-next-minor, and F-362's own suite-green proof establishes the clean baseline it hands over.
- **Coverage-claim inflation**: carrying "50/50" forward without re-derivation. *Mitigation*: FR-4 is decisive; PM vetoes at spec review if unmet. A Partial downgrade also edits `.claude/rules/scope.md` — a triad-visible governance change, not a doc tweak.
- **Consumer breakage on cutover**: downstream pipelines pinned to 2025 identifiers misread 2026 codes; token-grammar drift additionally risks a silent 0/10 CA page (`classify_framework_items` exact-equality). *Mitigation*: FR-6 ADR decided before mechanics; FR-11b unmatched-ref warning; changelog migration note.
- **Citation link-rot manufacture (architect MEDIUM-5)**: re-anchoring 54+ edge citations to 2026 URLs changes the monitored set consumed by `check-citation-urls.py` and the weekly link-rot workflow — #332 is already open with 41 findings. *Mitigation*: apply the #183/T021 lesson — validate via a **live monitor dispatch at deliver**, not deferred.
- **Immutable-record rewrite**: naive sweep would rewrite 955 refs across 114 protected files. *Mitigation*: FR-8 exclusion list is a hard boundary; init-baseline-tree regenerates by script, same-commit, never hand-swept.
